# インポートファイル仕様

旧 Cafe Timer から書き出したデータを、新アプリの設定画面からインポートするためのファイル仕様。
実装は [src/worker.js](src/worker.js) の `POST /api/import`、UI 側は [public/js/app.js](public/js/app.js) の `data-form="import"`。

設定画面の「データのエクスポート」(`GET /api/export`)が出力するファイルは、この仕様どおりで、そのままインポートできる。

## 1. ファイル形式

- 形式: JSON(UTF-8)。拡張子は `.json`
- ルートは 1 つのオブジェクト
- 3 つのキー `taps` / `relationship` / `profile` はすべて**任意**。含まれているものだけが取り込まれる
- 上記以外のキー(`schema` など)は無視される
- JSON として解釈できないファイルは、サーバーに送る前にエラー表示(`badJson`)になる

```json
{
  "schema": 1,
  "taps": [
    { "id": "0192f3a4-5b6c-7d8e-9f01-23456789abcd", "tap_time": "2026-10-31T19:05:12.000Z" }
  ],
  "relationship": [
    {
      "id": "0192f3a4-5b6c-7d8e-9f01-23456789abce",
      "char_key": "airi",
      "bond_level": 20,
      "recorded_at": "2026-10-31",
      "created_at": "2026-10-31T10:00:00.000Z",
      "updated_at": "2026-10-31T10:00:00.000Z"
    }
  ],
  "profile": {
    "ticket1_time": "2026-10-31T08:00:00.000Z",
    "ticket2_time": null
  }
}
```

## 2. `taps`(タップ履歴)

配列。1 要素が 1 回のタップ。

| フィールド | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `tap_time` | string | 必須 | タップ時刻。`Date.parse` で解釈できる文字列。**UTC の ISO 8601 を推奨**(例: `2026-10-31T19:05:12.000Z`)。タイムゾーン表記のない文字列は解釈が環境依存になるので避ける |
| `id` | string | 任意 | UUID(`[0-9a-f-]{36}`、大文字小文字不問)。形式が合えばそのまま保持し、なければ `tap_time` から UUID v7 を新規生成する |

取り込み時の処理:

- 保存時に `tap_time` は `toISOString()` 形式に正規化される
- 4:00 JST 区切りの**論理月**ごとに `taps-YYYY-MM.json` へ振り分けられる
- 既存データと**同じ `id`** のタップは重複として読み飛ばす(`id` を省略した行は毎回新規 ID になるため、同じファイルを再取り込みすると重複する。旧データの ID は必ず付けること)
- 保存後は `tap_time` 昇順に並べ替えられる
- 3 時間ルール・60 秒の重複判定は取り込み時には**適用されない**

## 3. `relationship`(絆ランク履歴)

配列。1 要素が 1 回の記録。

| フィールド | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `char_key` | string | 必須 | キャラクターのキー。空文字不可、64 文字以内。例: `airi`, `airi_band`, `azusa_swimsuit`。キー一覧は [src/data/gamedata.js](src/data/gamedata.js) の `CHARACTERS[].key` |
| `bond_level` | integer | 必須 | 絆ランク。**1〜100 の整数**(小数・文字列は不可) |
| `recorded_at` | string | 必須 | 記録日。**`YYYY-MM-DD` 形式のみ**(時刻付きは不可) |
| `id` | string | 任意 | UUID。形式が合えば保持、なければ新規生成 |
| `created_at` | string | 任意 | ISO 8601。解釈できなければ取り込み時刻 |
| `updated_at` | string | 任意 | ISO 8601。解釈できなければ取り込み時刻 |

取り込み時の処理:

- 上記の必須条件を満たさない行は読み飛ばす(`skipped` に計上)
- **`(char_key, bond_level)` が既存データと同じ行は重複として読み飛ばす**(ファイル内の重複も、先に処理された方だけが残る)
- `char_key` が `gamedata.js` に存在するかは**検証しない**。旧アプリのキーが新アプリのキャラ一覧にない場合、取り込みは成功するが画面には表示されない可能性がある
- `relationship` が配列でない場合は、そのキーごと無視される

## 4. `profile`(チケット)

オブジェクト。

| フィールド | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `ticket1_time` | string \| null | 任意 | チケット 1 を使った時刻(ISO 8601) |
| `ticket2_time` | string \| null | 任意 | チケット 2 を使った時刻(ISO 8601) |

取り込み時の処理:

- ISO 8601 として解釈できる値のみ上書きする。`null` や不正な値は**既存の値を変更しない**(クリアはできない)
- `timezone` など他のフィールドは取り込まれない
- 既存のチケット時刻は、ファイルの値で**上書き**される(タップ・絆のようなマージはしない)

## 5. 結果の通知

取り込み後、次の件数がトーストで表示される。

| 項目 | 内容 |
| --- | --- |
| `taps` | 新規に追加したタップ数 |
| `relationship` | 新規に追加した絆記録数 |
| `skipped` | 読み飛ばした件数(不正な行、`id` 重複のタップ、重複・不正な絆記録) |
| `profile` | プロフィールを更新したか(`true` / `false`。トーストには出ない) |

## 6. 制約と注意

- 取り込みは何度実行しても安全(追加のみで、既存データを削除しない)。ただし `taps` は `id` が揃っている場合に限る
- ファイル全体が 1 回のリクエストで送られる。サイズ上限は Cloudflare Workers のリクエスト上限に従うため、極端に大きいファイルは分割すること
- 取り込みには Google ログインと Drive の認証(`X-Drive-Token`)が必要
- 旧アプリ側の書き出し機能が出力する形式は、この仕様に合わせること(移行計画は [Cafe Timer リニューアル 設計書・開発計画.md](Cafe%20Timer%20リニューアル%20設計書・開発計画.md) の 11 章を参照)
